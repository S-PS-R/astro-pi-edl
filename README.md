# Astro Pi EDL

Sense HAT V2 re-entry simulation and Raspberry Pi drop recording for an EDL
flight-computer demo. Simulated atmospheric conditions and physical measurements
are kept separate.

## Install and run

From the repository root, activate your virtual environment and install everything:

```sh
python -m pip install -e .
```

`src/edl_sense_hat_emulator.egg-info/` is generated by pip/setuptools during
installation. It records the package name, version, dependencies and source-file
list. It is ignored by Git and should not be edited or committed.

Tkinter is required for the GUI. For Pi OS hardware packages, I2C and calibration
setup, follow [Raspberry Pi setup](docs/raspberry_pi_setup.md).

| Task | Command |
| --- | --- |
| Open the independent sensor emulator | `python -m sense_hat_emulator` |
| Initialize entry and open live status (desktop) | `python -m edl_flight_computer.run --emulator` |
| Initialize entry and open live status (Pi hardware) | `python -m edl_flight_computer.run` |
| Generate entry data | `python data/create_atmospheric_data.py` |
| List body presets | `python data/create_atmospheric_data.py --list-bodies` |
| Replay entry data in the emulator | `python tools/calibration/check_sensors.py --csv data/atmospheric_entry/entry.csv` |
| Select JSON and plot | `python tools/plot_atmospheric_data.py` |
| Check real Pi sensors | `python tools/calibration/check_sensors.py` |
| Verify Pi sensor settings | `python tools/calibration/check_sensor_profile.py` |
| Launch IMU calibration | `python tools/calibration/calibrate_imu.py` |
| Record a physical drop | `python -m edl_flight_computer.record_drop` |
| Run tests | `python -m unittest discover -s tests -v` |

`data/__init__.py` makes the generator directory a regular Python package for
imports and tests. It contains no simulation logic and is not part of a generated
run. The `__init__.py` files under `src/` expose the emulator and flight-computer
packages. Importing these packages does not open hardware or a GUI.

## Sensor emulator

### Live flight status

`edl_flight_computer.run` initializes sensors, enters `ENTRY`, and continuously
reads sensors until Ctrl+C. Its small read-only window shows the selected source,
connection/read status, phase, elapsed time, telemetry age and environmental/IMU
readings. The phase and initial entry conditions remain unchanged until you add
descent calculations. This command does not yet log a flight or run deployment logic.

The window runs in a separate process and receives display updates at about
10 Hz. Closing it leaves sensor acquisition and terminal status running. If the
window cannot open, the flight program continues in the terminal. Use
`--no-window` for terminal-only operation. Hardware is required unless
`--emulator` is explicitly selected. Stop the program with Ctrl+C in the terminal.

### Independent sensor controls

```python
from sense_hat_emulator import SenseEmu

sense = SenseEmu(noise=False, realtime=False, seed=42)
sense.set_temperature(25)
sense.advance(0.08)
print(sense.get_temperature())
```

Pass the same board instance to components that share readings and LEDs.

| Sensor module | Getter/setter names (prefix with `get_` or `set_`) | Units |
| --- | --- | --- |
| `humidity.py` | `humidity`, `temperature_from_humidity` | %RH, degrees C |
| `pressure.py` | `pressure`, `temperature_from_pressure` | hPa, degrees C |
| `imu.py` | `accelerometer_raw`, `gyroscope_raw`, `compass_raw` | g, rad/s, microtesla |

Vector setters accept x/y/z or a dictionary. `set_temperature()` updates both
temperature targets; `get_temperature()` reads the humidity source. Gyro readings
are angular rates, not orientation. Attitude and flight-state estimation belong
in flight code.

`emulator.py` manages the shared API, clocks, CSV replay and LEDs; `gui.py`
provides the display; `hardware_profile.py` defines the fixed reference profile.

### Fixed rates and ranges

| Sensor group | Nominal output rate | Modeled range |
| --- | --- | --- |
| Accelerometer | 119 Hz | +/-8 g per axis |
| Gyroscope | 119 Hz | +/-500 degrees/s, returned in rad/s |
| Magnetometer | 20 Hz | +/-400 microtesla per axis |
| Pressure and its temperature | 25 Hz | 260-1260 hPa; -30 to 105 degrees C |
| Humidity and its temperature | 12.5 Hz | 0-100%RH; -40 to 120 degrees C |

These are upstream RTIMULib defaults, with no runtime sensor-rate controls.
Existing Pi settings can override defaults: verify them using the profile checker.
See [sensor timing](docs/sensor_timing.md) for driver sources and limitations.
Python/Linux polling is not a guarantee of exact hardware sample timing.

Setters change physical targets immediately; getters return the last sample on
the appropriate sensor clock. Faster calls do not create samples. Manual time
moves only through `advance(seconds)`; real-time mode catches up to a monotonic
clock on access. GUI refresh is approximately 30 Hz, independent of sensor ODR.

`noise=False` returns unperturbed values at the fixed sensor ticks.
`noise=True` adds seeded Gaussian noise to each channel and limits the reading
to its modeled range. All sensor files use explicit true-value, noise, reading
and limit calculations, without moving averages or resolution rounding.
The per-sample noise magnitudes are retained from the earlier model, so removing
averaging makes the displayed noise more noticeable. These synthetic magnitudes
still need calibration against real measurements; they are not accuracy guarantees.
Resetting/toggling noise restarts random sequences and clocks. Public readings outside
modeled ranges return `OVR` (-1e6); the real driver does not necessarily do this.
Physical targets remain available internally through `sense._state.snapshot()`.

### Replay and LEDs

```python
sense.load_csv("data/atmospheric_entry/entry.csv")
sense.advance(1.0)  # when realtime=False
```

Required CSV columns are `time_s`, `temperature_humidity`, `temperature_pressure`,
`pressure`, `humidity`, `accel_x/y/z`, `gyro_x/y/z` and `mag_x/y/z` (each axis is a
separate column). Time starts at zero and strictly increases. Extra columns are
rejected. Optional `led_r`, `led_g`, `led_b` must appear together, with integer
values from 0 to 255. Altitude/orientation reference data belongs in JSON.

Rows change targets; sensors sample held targets on their independent clocks.
Replay has no added noise by default, but readings need not update at every row.
EOF holds final targets while sensor clocks continue; pause freezes the clock.
Restart restores the first targets. Controls are `pause_replay`, `resume_replay`,
`restart_replay`, `stop_replay` and `get_replay_status`. Noise can be enabled.

LED methods are `clear`, `set_pixel/get_pixel`, and `set_pixels/get_pixels`, with
RGB565 readback. CSV colours apply at row timestamps. Joystick and scrolling text
are not emulated.

## Entry data and plots

```sh
python data/create_atmospheric_data.py --body lifting_capsule --atmosphere layered --output-dir data/my_entry
```

```python
from data.create_atmospheric_data import create_atmospheric_data

result = create_atmospheric_data(
    body="lifting_capsule",
    entry_altitude_m=120000,
    entry_velocity_m_s=7800,
    entry_fpa_deg=-6.5,
    atmosphere="layered",
    lift_to_drag=0.35,
    output_dir="data/my_entry",
)
print(result["paths"], result["termination_reason"])
```

Defaults: blunt capsule, 120 km geometric altitude, 7800 m/s and -6.5 degrees
from local horizontal (negative downward). Velocity is relative to a nonrotating
Earth/atmosphere. These are illustrative inputs, not a mission reconstruction.

Presets are sphere, blunt capsule, lifting capsule and box. `--list-bodies` shows
mass, reference area, Cd, L/D, nose radius and ballistic coefficient. Explicit
overrides win; custom bodies require all five properties. L/D=0 is ballistic;
positive L/D is zero-bank lifting entry. Mass, Cd and L/D stay constant.

Each run writes only:

- `entry.csv`: emulator-compatible environmental and board-axis sensor targets.
- `entry.json`: settings, units, sources, assumptions, summary, hardware-range
  violations and trajectory samples; self-contained for plotting.

`output_dir` selects the folder. Legacy `output_path` selects an exact CSV name
and matching JSON stem; the two options cannot be combined. Existing output
names are overwritten. No trajectory CSV or plot image is generated.

`sample_rate_hz` / `--sample-rate-hz` defaults to 20 Hz and controls scenario
resolution, not sensor ODR. It cannot resolve motion faster than the source rows.
The final row is at the event time, possibly with a shorter interval.

The plot tool opens a JSON picker and one figure containing:

1. Altitude (Y) vs density (X).
2. Altitude (Y) vs velocity (X).
3. Altitude (Y) vs X/Y/Z acceleration (X).
4. Altitude vs time.
5. Velocity vs time.
6. X/Y/Z acceleration vs time.

Save manually using the figure toolbar. Acceleration is board-axis specific
force in g. The plotter uses JSON only and does not save images automatically.

### Model assumptions and sources

Motion includes inverse-square gravity, drag, lift and integrated convective
heat load in a vertical Cartesian plane. Stop conditions are pre-impact surface
intersection, upward departure through 150 km, or a 7200 s time limit. There are
no parachutes, thrust, impact pulses or post-impact landing samples.

| Atmosphere | Behavior |
| --- | --- |
| `exponential` (default) | Isothermal pressure/density decay; surface 288.15 K, 101325 Pa, about 1.225 kg/m3, H=8434.51 m |
| `lecture` | H=1/1.38e-4=7246.38 m |
| `layered` | US76 hydrostatic layers to 86 km, tabulated interpolation to 150 km |

`scale_height_m` can override either exponential model. Reference surface density
stays fixed; temperature and pressure are derived consistently. Layered mode
rejects scale-height overrides and approximates the upper atmosphere.

Temperatures are ambient proxies; pressure is static. Humidity is an assumed
profile from 85% at sea level to 0% by 30 km, holding the final node above it.
Near-vacuum RH is a placeholder. Override altitude/RH pairs using
`humidity_profile` or a JSON array passed to `--humidity-profile`.

Default board +Z opposes velocity, +X follows lift, and +Y completes the
right-handed frame. `mounting_deg=(roll,pitch,yaw)` gives board-to-default
Rz(yaw) Ry(pitch) Rx(roll). Acceleration excludes gravity; gyro follows the same
prescribed attitude. Rotational dynamics are not solved. Magnetic field defaults
to (25,0,40) microtesla NED, north along downrange, scaled inversely with radius
cubed. This is an illustrative field, not a location-specific prediction.

Sutton-Graves heat flux is `1.7415e-4*sqrt(rho/Rn)*V**3` W/m2. It estimates
hypersonic stagnation convection, not internal temperature, shock radiation,
ablation or survival. Outside that regime it is an engineering proxy. CSV targets
are unclipped; readings may show OVR. Peak statistics depend on source resolution.

Sources: Lecture 3 AFM Part 1 (forces); Lecture 3 AFM Part 2, PDF pages 12-15 and
65-75 (scale height/Allen-Eggers); Lecture 4, PDF pages 5-10 and 74-77
(lifting entry/Sutton-Graves); [US76](https://ntrs.nasa.gov/citations/19770009539)
and [PDAS tables](https://www.pdas.com/bigtables.html). Sources are also in JSON.

## Real sensors, calibration and drop recording

`tools/calibration/check_sensors.py` requires hardware unless `--csv` explicitly
selects emulation. `--monitor` stays in the current terminal; otherwise it tries
a Linux desktop terminal. Printing is about once per second, independent of ODR.

`check_sensor_profile.py` reads `~/.config/sense_hat/RTIMULib.ini`, compares IMU
rates/ranges and never edits settings. `calibrate_imu.py` launches RTIMULibCal;
follow its instructions and verify SenseHat() uses the resulting calibration.

| Flight-computer module | Responsibility |
| --- | --- |
| `hardware.py` | Shared real/emulated board connection; hardware-required mode never falls back |
| `sensors.py` | Independent environmental and raw IMU readers |
| `record_drop.py` | Fixed-profile polling and continuous capture |
| `telemetry.py` | Local CSV flushed after every row |

The drop recorder requires hardware by default; `--emulator` explicitly enables
a desktop test. `--duration-s 30` limits capture; otherwise Ctrl+C or joystick
centre stops it. Blue LEDs indicate recording and clear on exit. All capture
is raw sensor data; no release, impact or landing events are inferred. It does not automatically plot or send network messages.

Output is a new timestamped `logs/drop_*.csv`; `--output` chooses a new filename.
Existing recordings are never overwritten. Rows include environmental/raw IMU
readings and per-group poll timestamps. These are actual
poll times, not chip data-ready timestamps; scheduling/API delays can miss samples.

Landing detection is left for you to implement. The phase controller, physically
induced fault response, countdown and
text/email/social landing notification remain to be implemented. The offline
atmospheric scenario is a re-entry test input, not a prediction of the physical drop.
